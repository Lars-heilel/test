# download-benchmark

Консольный бенчмарк скорости скачивания по URL на **NestJS + TypeScript**.

Скрипт делает **10 последовательных HTTP-запросов** к указанному адресу, каждый раз дожидается полного получения тела ответа, затем печатает:

- среднее время одного запроса;
- суммарный объём скачанных данных;
- скорость скачивания.

## Требования

- Node.js **20 или новее** (проверено на Node 26).
- npm.
- Доступ в интернет к проверяемому адресу.

## Установка

```bash
git clone https://github.com/Lars-heilel/test.git
cd download-benchmark
npm install
```

## Запуск

```bash
npm start -- https://example.com/image.jpg
```

`npm start` сначала собирает проект (`nest build`), затем запускает `dist/main.js` с переданным адресом.

Без пересборки:

```bash
npm run build
node dist/main.js https://example.com/image.jpg
```

Режим разработки с пересборкой при изменениях:

```bash
npm run start:dev
```

Справка:

```bash
node dist/main.js --help
```

## Пример вывода

```text
Целевой адрес: https://example.com/image.jpg
Запросов: 10 (успешных: 10, ошибок: 0)
Среднее время запроса: 214.7 мс
Всего скачано: 12.40 MB
Скорость скачивания: 5.77 MB/с
```

## Единицы измерения

| Величина | Единица | Пояснение |
| --- | --- | --- |
| Время запроса | миллисекунды (мс) | Среднее арифметическое по успешным запросам |
| Объём | B, KB, MB, GB (десятичные) | 1 KB = 1 000 байт, 1 MB = 1 000 000 байт |
| Скорость | KB/с, MB/с, GB/с | Суммарный объём ÷ суммарное время успешных загрузок |

Скорость считается как `суммарный объём / суммарное время успешных загрузок`, а не как среднее арифметическое скоростей отдельных запросов.

## Поведение и ошибки

- Ровно 10 запросов за запуск, строго последовательно, без параллелизма.
- Редиректы обрабатываются автоматически (переход по `Location`).
- Таймаут одного запроса — 30 секунд.
- Ответы 4xx/5xx считаются неуспешными, не входят в средние метрики и перечисляются в конце отчёта.
- Пустое тело ответа не приводит к делению на ноль: скорость выводится как `н/д (нет данных)`.
- Если не удалось выполнить ни одного запроса, код возврата — `1`.
- При частичных ошибках метрики считаются по успешным запросам, в stderr выводится предупреждение, код возврата — `0`.
- URL без схемы или со схемой, отличной от `http`/`https`, отклоняется до начала замеров.

## Тесты

```bash
npm test          # unit-тесты (Jest)
npm run test:e2e  # сборка + end-to-end тесты CLI
npm run test:cov  # покрытие
```

Тесты не используют моки сети: поднимается реальный локальный HTTP-сервер, проверяются последовательность запросов, объём, ошибки 500, пустое тело, сетевые ошибки и таймаут.

## Архитектура

```text
src/
  main.ts                     # bootstrap Nest-контекста, коды возврата
  app.module.ts               # корневой модуль
  benchmark/
    benchmark.module.ts       # DI-провайдеры, внедрение fetch
    benchmark.service.ts      # 10 последовательных загрузок и замеры
    benchmark.constants.ts    # REQUEST_COUNT, таймаут, токен FETCH_CLIENT
    benchmark.types.ts        # Attempt / Summary / Result
    summary.ts                # чистая агрегация метрик
  cli/
    cli.module.ts
    cli.service.ts            # оркестрация: парсинг → замер → отчёт → код возврата
    cli.parser.ts             # валидация аргументов
    report.formatter.ts       # форматирование и единицы измерения
    cli.output.ts             # абстракция вывода (удобно тестировать)
test/
  cli.e2e-spec.ts             # запуск собранного CLI как процесса
test-support/                 # локальный HTTP-сервер и фабрики данных
```

Ключевые решения:

- `fetch` внедряется через DI-токен `FETCH_CLIENT` — сервис не зависит от глобального состояния.
- Вывод абстрагирован токеном `CLI_OUTPUT` — CLI-тесты не перехватывают `console`.
- Агрегация вынесена в чистую функцию `summarize`, поэтому метрики тестируются без сети.
- Строгий TypeScript (`strict: true`), сборка через Nest CLI.

## Ограничения

- Результат зависит от кэширования CDN и состояния сети; для сравнения запускайте несколько раз.
- Авторизация, cookies и пользовательские заголовки не поддерживаются — проверяются публично доступные адреса.
