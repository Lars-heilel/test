# Feature Specification: Консольный бенчмарк скорости скачивания по URL

**Feature Branch**: `001-download-benchmark`
**Created**: 2026-11-13
**Status**: Draft
**Input**: User description: "Консольный скрипт: принимает адрес, делает 10 последовательных запросов с ожиданием полного ответа, считает среднее время запроса и общий объём скачанных данных, печатает скорость скачивания. Единицы измерения указать в README. Загрузить на GitHub с README."

## User Scenarios & Testing *(mandatory)*

### Primary User Story

Разработчик хочет быстро измерить, насколько быстро его сеть/сервер скачивает файл по заданному адресу. Он запускает скрипт из терминала, передаёт URL (например, ссылку на тяжёлую картинку), получает по окончании 10 последовательных загрузок понятный отчёт: среднее время одного запроса, суммарный объём скачанных данных и скорость скачивания в выбранных единицах.

### Acceptance Scenarios

1. **Given** корректный HTTP(S)-адрес доступного файла, **When** пользователь запускает скрипт с этим адресом, **Then** скрипт выполняет ровно 10 последовательных запросов, каждый раз дожидаясь полного получения тела ответа, и завершается успешно.
2. **Given** 10 успешно выполненных загрузок, **When** скрипт формирует отчёт, **Then** он выводит: среднее время одного запроса, общий объём скачанных данных и скорость скачивания с явно указанными единицами измерения.
3. **Given** адрес, переданный аргументом командной строки, **When** пользователь запускает скрипт без дополнительных настроек, **Then** скрипт использует именно этот адрес и не требует интерактивного ввода.
4. **Given** недоступный адрес, неверная схема URL или сетевая ошибка, **When** пользователь запускает скрипт, **Then** скрипт выводит понятное сообщение об ошибке и завершается с ненулевым кодом возврата, не печатая вводящих в заблуждение метрик.
5. **Given** опубликованный репозиторий, **When** новый пользователь открывает README, **Then** он находит инструкцию по установке и запуску, а также явное описание единиц измерения времени, объёма и скорости.

### Edge Cases

- Адрес возвращает ответ без тела (например, 204 или пустой файл): скрипт должен корректно сообщить об отсутствии скачанных данных вместо деления на ноль или бесконечной скорости.
- Сервер отвечает ошибкой (4xx/5xx): скрипт должен явно сообщить о неуспешном ответе и не учитывать его как успешную загрузку.
- Редиректы: скрипт следует перенаправлениям и измеряет фактически полученный контент.
- Очень медленное соединение или таймаут: скрипт не зависает бесконечно и сообщает о проблеме.
- URL без схемы (например, `example.com/file.jpg`): скрипт либо нормализует адрес, либо выдаёт понятную ошибку валидации.
- Частичный обрыв соединения в середине загрузки: запрос считается неуспешным, отчёт не должен содержать недостоверных метрик.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Скрипт MUST принимать целевой адрес (URL) как аргумент командной строки.
- **FR-002**: Скрипт MUST выполнять ровно 10 запросов к указанному адресу последовательно, без параллелизма, и для каждого запроса дожидаться полного получения тела ответа.
- **FR-003**: Скрипт MUST измерять длительность каждого запроса и вычислять среднее время запроса по успешным загрузкам.
- **FR-004**: Скрипт MUST подсчитывать суммарный объём фактически полученных данных по всем успешным загрузкам.
- **FR-005**: Скрипт MUST вычислять и выводить скорость скачивания на основе суммарного объёма и суммарного времени успешных загрузок.
- **FR-006**: Скрипт MUST явно указывать единицы измерения времени, объёма и скорости в консольном выводе: время — миллисекунды (мс), объём — B/KB/MB (1 KB = 1 000 байт, 1 MB = 1 000 000 байт), скорость — MB/с (KB/с для малых значений).
- **FR-007**: Скрипт MUST завершаться с ненулевым кодом возврата и понятным сообщением при невозможности выполнить загрузки (недоступный хост, ошибка протокола, ответ с ошибочным статусом).
- **FR-008**: README MUST содержать инструкцию по установке зависимостей и запуску скрипта с примером, а также описание используемых единиц измерения.
- **FR-009**: Решение MUST быть опубликовано в публичном репозитории на GitHub вместе с README и исходным кодом.
- **FR-010**: Скрипт MUST корректно обрабатывать отсутствие тела ответа и не выдавать деление на ноль или некорректные метрики.

### Key Entities

- **Загрузка (Download attempt)**: один запрос к целевому адресу; характеристики — порядковый номер, статус успеха/неуспеха, длительность, объём полученных данных, код ответа.
- **Отчёт (Report)**: агрегированный результат прогона; характеристики — целевой адрес, число успешных/неуспешных загрузок, среднее время запроса, суммарный объём, скорость скачивания и единицы измерения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь может запустить скрипт одной командой, указав только URL, без правки кода или конфигурационных файлов.
- **SC-002**: Для доступного файла скрипт выполняет ровно 10 загрузок за один запуск и выводит отчёт, содержащий все три метрики (среднее время, суммарный объём, скорость) в 100% успешных прогонов.
- **SC-003**: Отчёт читается без обращения к документации: единицы измерения указаны рядом с каждым числом.
- **SC-004**: Ошибочные сценарии (недоступный адрес, ответ 4xx/5xx, пустое тело) завершаются понятным сообщением и ненулевым кодом возврата в 100% проверенных случаев.
- **SC-005**: Новый пользователь, следуя README, успешно запускает скрипт с первой попытки.

## Assumptions

- Язык реализации — Python или Node.js на выбор исполнителя (ограничение из запроса); конкретный выбор не влияет на требования спецификации.
- Пользователь запускает скрипт в терминале на машине с доступом в интернет.
- Аутентификация, cookies и заголовки запроса не требуются; проверяется публично доступный адрес.
- Сложные форматы вывода (JSON, CSV) не требуются — достаточно читаемого текстового отчёта в консоли.
- Сценарий «тяжёлая картинка» — типовой пример, но скрипт работает с любым HTTP(S)-адресом.
